Current authority/schedule: [production milestones](production-milestones.md); actual M1 execution: [M1 validation](m1-validation.md).

## Strategy and automation boundaries

Most tests exercise deterministic domain behavior without a browser. Add a small set of rendered integration tests, then a compact browser suite proving complete journeys and platform behavior. Manual review covers narrative accuracy, pacing, visual quality, touch ergonomics and assistive technology behavior that assertions cannot establish.

Proposed tools after approval: Vitest; Testing Library + DOM test environment for essential component integration; Playwright Test with browser binaries; `@axe-core/playwright`; TypeScript; ESLint; npm dependency audit. Use project-local versions and a lockfile. Existing Node meets current documented Vite/Vitest minimums, but actual dependency setup/browser launch must pass Phase 1. [Vitest](https://vitest.dev/guide/), [Playwright](https://playwright.dev/docs/intro), [axe integration](https://playwright.dev/docs/accessibility-testing).

No tests that merely restate CSS classes or mirror reducer internals. No full-page text snapshots that make story edits painful. Expected scores must be independently calculated from the rubric, not computed by the same production scorer inside the assertion. Avoid arbitrary sleeps; await meaningful accessible state. Failed screenshots/traces need review, not automatic baseline acceptance.

## Unit suite (automated, Phase 2 onward)

| ID | Cases and expected invariant |
|---|---|
| U01 Narrative progression | Every line advances once; wrong/stale node/line ignored or rejected; every chapter reaches its investigation and next chapter |
| U02 Branch conditions | Every authored option/outcome; flags with true/false; first-match order/fallback; required safe-path bridges for C1→C2, C2→C3 and C3→recovery preserve withheld data/codes and never dispatch risky actions |
| U03 Evidence | Only available artifact details discoverable; one record per clue; hover/mount/tab switch do not discover; unavailable/future IDs rejected |
| U04 Journal/credit timing | Journal contains only discoveries; pre-commit snapshot frozen; later comparison discovery labeled after-choice; backlog cannot farm credit |
| U05 Decision integrity | One committed option per decision; 2–3 valid options; guards/preconditions; no evidence quota; double-click and stale event cannot duplicate effects |
| U06 Verification | Source-panel opening/mount/focus/scroll and Verify selection earn zero; explicit authored detail inspection required; comparison is separate; invalid target/compare-before-inspection rejected; completed work reused once |
| U07 Scoring | Adopted v1 golden traces and hand-calculated fractions/percentages/rounding; maxima/zero/mixed; repeated inspection cannot change score; no timing bonus; expected results never generated by production scorer |
| U08 Recovery | No-risk preventive context; link-only possible-exposure context; data/account exposure variants; same three objectives/denominators; wrong action still advances through feedback |
| U09 Report | Behavior-dependent neutral Indonesian descriptions/recommendations; each clause supported by history; no achievement tier or threshold label; missed vs late evidence; no real-offer safety claim; report only on completion |
| U10 Serialization | Save round trip preserves exact cursor and history; IDs/versions/revision validate; duplicate/future/impossible events rejected |
| U11 Invalid saves | Malformed JSON, null/array/object confusion, unknown keys/prototype-style fields, oversized payload/event log, obsolete/future versions, unknown IDs, invalid event ordering |
| U12 Persistence adapter | Read/write/remove failures and quota; memory-only mode; incompatible save not overwritten on first render; reset removes only owned keys |
| U13 Content graph | Unique IDs, valid edges, all options/variants have feedback and forward route, source/evidence references valid, no unintended cycle, maxima attainable |
| U14 Restart/conflicts | No old evidence/choice/flags/score after restart; completed save can replay; other-tab update detected before ordinary subsequent writes and requires choice |
| U15 Safety content policy | Artifact domain labels `.example`; internal artifact destinations only; no HTML/script predicates, sensitive-input fields or external phishing resource URLs |

Engine transition coverage matters more than a global line percentage. Require all core decision options and each rubric criterion to have meaningful passing/failing cases. If coverage tooling is used, treat it as a gap detector; do not add superficial tests to reach a vanity number.

Use Chromium as frequent smoke browser. Before release, run critical journey/deep routes in Firefox and WebKit if official browser installation is working; at minimum manual second-engine/device evidence and clearly documented gaps. Golden expectations are maintained in the “Golden fixtures v1” section of the [scenario schema](scenario-data-schema.md), including complete action traces, per-competency arithmetic, outcome framing and no-credit controls. These fixtures are documented now; automated test files wait for implementation authorization.

Domain-level exhaustive options: D1–D3 = 9 option outcomes; recovery variants/checkpoints tested individually. Full browser suite covers representative safe/risky/mixed journeys rather than all 27 combinations times every recovery path; pure graph/engine tests provide broader coverage.

## Visual, content and usability review (manual)

- Screenshot S01–S09 representative states at 1440, 768, 390 and 360 px. Check long Indonesian strings, domains, report zeros, empty journal, debrief, invalid save and drawer focus. Reflow check at 320 CSS px.
- Inspect production build, not only dev server: typefaces actually loaded, art sizes, contrast, focus, no overlap/sideways page scroll, sticky prompt not obscuring tasks. Use Taste app-screen workflow for play/report; landing rules separately with documented project exceptions.
- Small baseline screenshot set only after layout stabilizes: email workspace, mobile chat/journal and report. Keep same OS/font/viewport for comparisons; inspect changes, don't accept all diffs automatically.
- Product Owner reads all authored outcomes/feedback for accuracy: no HTTPS/typo certainty, no claim link opening equals compromise, no shaming, safe-path narrative bridges coherent, remediation relevant to exposure.
- Review each safe-path bridge against the actual preceding choice: blocked recruiter remains blocked, portal review stays an inert investigation artifact, and careful Ari enters hypothetical recovery. Neutral Indonesian report statements must match history without unapproved achievement labels.
- Two or three representative fresh-player sessions if available (not a validation study): can discover controls without answers being exposed, understand comparisons, complete all chapters, find guide, understand score limitations. Measure natural completion time against 12–18 minutes; do not force pacing with timers.
- Manual keyboard and screen reader read-through, ideally Windows Narrator/NVDA if available; availability unverified today. Confirm focus and announcements, not only labels in code.
- Maintain final asset/license/AI-provenance ledger. Check no real company impersonation/photo, credential/upload field or active deceptive address remains.

## CI and build gate proposal

After the repository exists: clean lockfile-based install; content validation; TypeScript validation; lint; unit/integration tests; production build; preview-server browser smoke. Planned script contract: `typecheck`, `lint`, `test:unit`, `test:integration`, `validate:content`, `build`, `test:e2e`. Exact scripts are Phase 1 work and do not exist yet. Vite's build is not a substitute for typechecking. [Vite TypeScript](https://vite.dev/guide/features#typescript)

Dependency review runs once the tree exists, and after material dependency changes. Examine direct/transitive and dev dependencies; severity, reachability and fixes determine action. No unresolved exploitable critical/high runtime vulnerability at release; justified dev-only residuals need written rationale. Never auto-upgrade majors via forced audit fixes. npm audit transmits dependency metadata to the registry; this is a development check, not gameplay telemetry. [npm audit](https://docs.npmjs.com/cli/v10/commands/npm-audit/)

Visual/design guideline review fetches the current upstream rules at that review, as required by the installed skill. Do not claim a score or zero failures for scripts not executed.

## Production smoke and submission gate

Run against the **public production URL**, independently of localhost and the logged-in hosting session:

1. Fresh private/incognito visitor reaches app without deployment-auth wall; HTTPS valid; JS/CSS/images load with correct MIME types.
2. Direct `/play`, `/report`, `/guide`, unknown route and refresh work; static asset fallback has not served HTML for missing JS.
3. Complete a clean representative game and observe real report; refresh/resume/replay; no critical console/page errors.
4. Mobile/keyboard smoke; source comparison, journal and recovery usable. Verify CSP/security headers don't block app/fonts/styles.
5. Network inspection: simulation remains in-app; no live fake login, document upload, OTP/payment processing or unexpected third-party content calls.
6. Public GitHub repository readable signed-out, owned by approved leader, matching final release commit; README has setup, build/test commands, live link, limitations and credits.
7. Documentation matches implemented rubric/schema/architecture. Demo video <=5:00, accessible link, shows user-dependent core feature and report; final submission links checked.
8. Record commit, deployment identifier/URL, browser/device, date/time **with timezone**, pass/fail and residual limitations. Keep known-good commit ready to redeploy.

Release blockers: cannot complete game; broken direct routes; wrong/double-counted scoring; inaccessible core controls; sensitive input or outbound simulation; invalid save causing blank screen; public URL/repo inaccessible; missing required submission artifacts. Cosmetic refinements can be deferred; these cannot. No production test is possible until deployment is authorized and exists.
