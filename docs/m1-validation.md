# M1 — Chapter 1 implementation and validation

29 October 2026. **M1 is implemented and locally validated.** Full production authority is recorded in [milestones](production-milestones.md). This report does not reopen a vertical-slice approval gate. No Git operation, public deployment or submission was performed.

## Implemented functionality

- Start/continue/restart/delete, safety briefing, original Ari desk illustration, four-line narrative and read-only story backlog.
- Fictional recruitment inbox with explicit sender, deadline and destination inspections; a campus decoy demonstrates that imperfect writing is not proof of fraud.
- GDD C1-E01–E04 and D1 retained. Each explicit inspection records one discovery; the journal exposes only discovered clues and contextual cautions. Opening/focusing/scrolling UI earns nothing.
- Independent careers directory with deliberate detail inspection and separate claim/reference comparison. Selecting Verify alone records no verification work and cannot skip its pending task.
- Explicitly committed choices: follow the simulated link, ignore, or pause to verify. Each reaches distinct consequence, explanation, applicable next action and a coherent shared handoff. Opening a link is possible exposure, never treated as proven compromise. There is no clue quota or game-over branch.
- Derived pre-choice evidence snapshot, two verification criteria and two safety criteria. Resolution-time evidence is marked after-choice and earns no retroactive Awareness. C1 fractions are chapter observations; no incomplete full-game/Recovery score or overall score is invented.
- Pure typed reducer, separate state/actions Context, bounded versioned event-log decoding/replay, exact cursor restore, memory-only play when storage fails, retry, invalid/incompatible-save protection, confirmed reset/replacement and multi-tab write conflict handling. Unsaved memory/conflict progress gets an exit warning. Saves contain no sensitive data or writable scores/flags/cursor snapshots.
- Responsive artifact navigation, tabs, native journal modal, visible focus and scene/route focus management. No real recruitment navigation, login/OTP/password/payment field, upload, telemetry or backend.

`chapterComplete` is the explicit C1/M1 checkpoint, not final game completion. M2 adds chapters/recovery and M3 adds the complete report; the reducer already chooses the next available chapter in scenario order.
